| Automation | A run is recorded when… | Trigger (`trigger_type`) | Actions listed |
|---|---|---|---|
| Private messages (Facebook, Instagram, WhatsApp) | your agent actually sent a reply | `message` | the reply |
| Emails (Gmail, Outlook, IMAP) | an incoming email was handled | `email` | the reply sent, or the draft saved |
| Comments (Facebook, Instagram) | a comment was handled | `comment` | the public reply, the private message |
| Comments (Facebook, Instagram), after the prospect's reply | a prospect sent their contact details in a private message, and the automation's follow-up actions ran | `message` | add to CRM, message to the prospect |
| Stories (Instagram) | a story reply was handled | `story_reply` | the reply |
| Lead Ads | a form was received and the lead created | `lead_ads` | message to the prospect, add to CRM — the run also carries the lead's ID |
| CRM sources | an action ran for an incoming contact | `crm_event` | message (email, WhatsApp), add to CRM — the run also carries the lead's ID when a lead was created |

Good to know:

- **No run when nothing happened.** A message your agent finally didn't answer produces no run.
- **Several messages in a row, one run.** Messages that arrive together and are answered together make a single run.
- **A Lead Ads automation with no action configured** still records a run, with the `success` status and an empty list of actions. While it's paused, its leads are created but no action runs.
- **No runs for the website chatbot.**
- **CRM sources:** Customer.io records a run for each contact it acts on. The other CRM sources (HubSpot, Typeform, Close, Monday, ClickUp, Tally, Odoo…) are relayed by a partner service that doesn't yet tell Agentova which automation handled an event: their runs are recorded only when the workspace has a single such CRM automation. A CRM workflow records one run per action.
- On comments, an action you didn't configure can show as `success`. This is a known limitation.
- Runs are kept for **90 days**, then deleted.
