The trigger fires for **the whole workspace**. To keep only some items (one source, one agent, only failures…), add an **If** or **Filter** node right after it — see [Example workflows](/n8n/recipes).

## What each event contains

Every execution receives one item with the envelope of the event:

| Field | Content |
|---|---|
| `id` | The event's unique ID (`evt_…`) |
| `type` | `lead.created`, `run.completed` or `automation.status_changed` |
| `created_at` | When the event happened |
| `data` | The lead, the run or the automation |

### Lead created

<LeadSources />

`data` contains: `id`, `source`, `agent_id`, `name`, `email`, `phone`, `custom_fields`, `created_at`.

### Run completed

<RunsByChannel />

`data` contains: `id`, `automation_id`, `status`, `trigger_type`, `occurred_at`, `actions` (each with its own `type` and `status`), `lead_id`.

### Automation status changed

`data` is the automation: `id`, `name`, `type`, `provider`, `agent_id`, `agent_name`, `status`, `updated_at`. Pausing an automation that's already paused changes nothing, so nothing fires.

## Activate the workflow

**Activating** the workflow registers it with Agentova; **deactivating** it removes the registration. You never manage that by hand.

To try it before activating, click **Listen for test event** (or **Execute step**), then make the event happen in Agentova — for example pause and reactivate an automation.

## Security and duplicates — handled for you

- **Signature check.** Every notification from Agentova is signed. The trigger checks the signature and its age (5 minutes at most) before starting the workflow. Anything unsigned, forged or replayed is rejected and never reaches your workflow.
- **Duplicates.** After a network problem, Agentova can send the same event again. The trigger remembers the events it has already processed (for 7 days) and starts the workflow **only once** per event.
- **Recovery.** If your n8n was unreachable for a long time, Agentova stops notifying it after three undelivered events in a row and notifies your workspace admins. The next time the workflow is activated (deactivate, then activate), the trigger notices it and registers again.
