description: "Que vérifier quand un workflow ne se comporte pas comme prévu"

## Le déclencheur ne se lance jamais

<AccordionGroup>
  <Accordion title="Le workflow est-il actif ?">
    Seul un workflow **actif** est enregistré auprès d'Agentova. Un workflow enregistré mais inactif ne reçoit rien (sauf pendant que vous cliquez sur **Listen for test event**).
  </Accordion>
  <Accordion title="Agentova peut-il joindre votre n8n ?">
    Votre instance doit être joignable depuis Internet en **HTTPS**, à l'adresse définie dans la variable `WEBHOOK_URL` de n8n. `localhost`, les adresses de réseau privé et le `http://` simple sont refusés par Agentova. Pour un test en local, un tunnel (Cloudflare Tunnel, ngrok…) qui fournit une adresse HTTPS publique fonctionne.
  </Accordion>
  <Accordion title="L'événement se produit-il vraiment ?">
    - **Lead Created** : seuls le formulaire de contact du chatbot, les Lead Ads, les appels téléphoniques, les prospects qui envoient leurs coordonnées après avoir commenté une publication et les contacts CRM entrants créent des leads. Un message privé ou un e-mail auquel votre agent répond n'en crée pas.
    - **Run Completed** : les sources CRM autres que Customer.io (HubSpot, Typeform, Close…) ne produisent des exécutions que si l'espace de travail n'a qu'une seule automatisation CRM de ce genre.
    - **Automation Status Changed** : mettre en pause une automatisation déjà en pause ne change rien, donc rien ne se déclenche. Supprimer une automatisation ou la désactiver dans l'application Agentova ne déclenche rien non plus.
  </Accordion>
  <Accordion title="S'est-il arrêté après une panne ?">
    Dès que trois livraisons d'affilée ont été abandonnées — chacune après jusqu'à 8 tentatives sur environ 27 heures et demie — et que les livraisons échouent depuis au moins 72 heures, Agentova désactive l'abonnement et alerte les administrateurs de votre espace de travail. **Désactivez, puis réactivez le workflow** : le déclencheur remplace l'abonnement désactivé.
  </Accordion>
  <Accordion title="L'API d'Agentova était-elle coupée ?">
    Les événements survenus pendant que l'API est coupée ne sont jamais livrés. Une fois qu'elle répond de nouveau, rattrapez-les avec les endpoints de liste de l'API (`GET /leads`, `GET /runs`, ou **Agentova → List** pour les automatisations).
  </Accordion>
  <Accordion title="Son abonnement a-t-il été supprimé dans Agentova ?">
    Les administrateurs de l'espace de travail peuvent supprimer des abonnements webhook dans **Paramètres → API**. Révoquer une clé supprime aussi, par défaut, les abonnements créés avec elle — et une clé est révoquée automatiquement quand l'administrateur qui l'a créée quitte l'espace de travail ou cesse d'être administrateur. Mettez à jour l'identifiant avec une clé valide si nécessaire, puis **désactivez, puis réactivez le workflow** pour vous réenregistrer.
  </Accordion>
</AccordionGroup>

## « Agentova Trigger: rejected a webhook delivery » dans les journaux n8n

Le champ `reason` indique pourquoi la notification a été refusée :

| `reason` | Que faire |
|---|---|
| `signature_mismatch` ou `no_secret` | La notification n'a pas été signée avec le secret de l'abonnement de ce nœud. Désactivez, puis réactivez le workflow pour obtenir un nouvel abonnement. |
| `stale_timestamp` | Vérifiez l'horloge du serveur n8n : elle doit être à l'heure (NTP). |
| `missing_signature`, `malformed_signature` ou `missing_body` | La requête ne venait pas d'Agentova : autre chose a appelé l'adresse du workflow. Elle a été refusée ; rien à faire. |

## Le même événement s'est exécuté deux fois

La mémoire des événements traités par le déclencheur vit dans le processus n8n : un redémarrage, ou plusieurs instances n8n en mode file d'attente (queue mode), peuvent laisser passer une livraison répétée. Ajoutez un nœud **Remove Duplicates** après le déclencheur, comme indiqué dans [Agentova Trigger](/n8n/trigger#sécurité-doublons-et-ordre).

## Activate échoue sur une automatisation e-mail

« This mailbox is already used by another active Agentova agent » : une boîte mail ne peut servir qu'à un seul agent actif, comme dans l'application Agentova. Détachez la boîte mail de l'autre agent dans l'application Agentova, puis relancez le nœud.

## « The Agentova API is temporarily unavailable »

Agentova a coupé son API pour un temps. Réessayez plus tard ; pour que le workflow continue, activez le réglage **Retry On Fail** du nœud.

## Le nœud ne trouve pas mon automatisation

- Elle a été supprimée ou désactivée dans l'application Agentova, ou son compte a été déconnecté : ces automatisations n'apparaissent pas.
- Elle appartient à un autre espace de travail : vérifiez l'identifiant utilisé par le nœud.
- C'est un agent téléphonique ou le chatbot du site web : ce ne sont pas des automatisations dans l'API.

## Limites

- Environ **100 requêtes par minute** par clé API, partagées par tous les workflows qui l'utilisent.
- **20 abonnements actifs** par espace de travail : chaque workflow actif doté d'un Agentova Trigger en utilise un, tout comme d'autres outils tels que Zapier.
- **10 clés API actives** par espace de travail.
