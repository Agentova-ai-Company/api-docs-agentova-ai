This guide takes you from zero to a working integration: an API key, a successful call, and a real webhook delivery you can inspect.

<Note>
  Every ID in this guide (`aut_...`, `whk_...`, `evt_...`, `lea_...`, `agt_...`) is an opaque, prefixed string — never a UUID, and never something you parse or validate.
</Note>

## Prerequisites

- An Agentova workspace where you're an **admin**, with at least one automation
- `curl` (or any HTTP client)
- A browser, to open a [webhook.site](https://webhook.site) URL

## Get started

<Steps>
  <Step title="Create your API key">
    In your Agentova workspace, go to **Settings → API** and create a key. It looks like `agk_live_<32 characters>` and is shown only once. One key gives you access to the entire workspace — there's no per-key scoping in v1.

    <Warning>
      Keep this key secret. Anyone with it can read your workspace's leads and runs, and pause or activate its automations.
    </Warning>
  </Step>

  <Step title="Make your first call">
    `GET /automations` doubles as a connection test — call it with `limit=1`:

    ```bash
    curl "https://core-api.agentova.ai/v1/automations?limit=1" \
      -H "Authorization: Bearer agk_live_your_key_here"
    ```

    A working key returns a paginated list:

    ```json
    {
      "data": [
        {
          "id": "aut_example123",
          "name": "Réponse aux commentaires — Agent SAV",
          "type": "social_comments",
          "provider": "instagram_page",
          "agent_id": "agt_example456",
          "agent_name": "Agent SAV",
          "status": "active",
          "updated_at": "2026-09-29T14:09:22Z"
        }
      ],
      "has_more": true,
      "next_cursor": "…"
    }
    ```

    Keep the `id` of one automation whose `status` is `active` — ideally one that isn't business-critical: you'll pause it in a moment. Only `active` and `paused` automations can be switched; a `draft` or `error` one returns `422`. A missing or revoked key returns `401 invalid_api_key` instead — see [Errors](/guides/errors).
  </Step>

  <Step title="Open a receiver for your first webhook">
    Go to [webhook.site](https://webhook.site) and copy the unique URL it gives you. You'll use it as the subscription target — no server of your own required for this guide.
  </Step>

  <Step title="Subscribe to an event">
    ```bash
    curl -X POST "https://core-api.agentova.ai/v1/webhooks" \
      -H "Authorization: Bearer agk_live_your_key_here" \
      -H "Content-Type: application/json" \
      -d '{
        "url": "https://webhook.site/your-unique-id",
        "events": ["automation.status_changed"]
      }'
    ```

    The response includes a `secret` — **shown only once**. It's what you use to verify the `X-Agentova-Signature` header of every delivery:

    ```json
    {
      "id": "whk_example789",
      "url": "https://webhook.site/your-unique-id",
      "events": ["automation.status_changed"],
      "created_at": "2026-09-29T12:53:00Z",
      "disabled_at": null,
      "secret": "whsec_your_secret_here"
    }
    ```
  </Step>

  <Step title="Make the event happen">
    <Warning>
      This pauses a real automation until you reactivate it. Run both commands back to back, and prefer a non-critical automation: while an email or CRM automation is paused, what arrives in the meantime isn't handled the usual way (see [Concepts](/guides/concepts#pausing-and-activating)).
    </Warning>

    Pause the automation you noted, then reactivate it:

    ```bash
    curl -X PATCH "https://core-api.agentova.ai/v1/automations/aut_your_automation_id" \
      -H "Authorization: Bearer agk_live_your_key_here" \
      -H "Content-Type: application/json" \
      -d '{"status": "paused"}'

    curl -X PATCH "https://core-api.agentova.ai/v1/automations/aut_your_automation_id" \
      -H "Authorization: Bearer agk_live_your_key_here" \
      -H "Content-Type: application/json" \
      -d '{"status": "active"}'
    ```

    Refresh the webhook.site page: two deliveries land, one per status change — usually within seconds — each with its `X-Agentova-Signature` header and a body like:

    ```json
    {
      "id": "evt_example012",
      "type": "automation.status_changed",
      "created_at": "2026-09-29T12:53:35Z",
      "data": {
        "id": "aut_example123",
        "name": "Réponse aux commentaires — Agent SAV",
        "status": "paused"
      }
    }
    ```

    See [Webhooks & signatures](/guides/webhooks-and-signatures) to verify the signature yourself.
  </Step>

  <Step title="Clean up">
    ```bash
    curl -X DELETE "https://core-api.agentova.ai/v1/webhooks/whk_your_subscription_id" \
      -H "Authorization: Bearer agk_live_your_key_here"
    ```

    `204` means the subscription is gone. You can also revoke the key in **Settings → API** if you created it only for this guide.
  </Step>
</Steps>

## Explore without a workspace

To discover the API without an Agentova account, run a mock generated from the contract (the same file the **API Reference** tab is built from). It answers every route with its documented examples, but it doesn't keep state, doesn't send webhooks and doesn't enforce rate limits.

```bash
npx @stoplight/prism-cli mock openapi/openapi-v1-draft.yaml
```

Then use `http://127.0.0.1:4010` instead of `https://core-api.agentova.ai/v1` in the commands above.
