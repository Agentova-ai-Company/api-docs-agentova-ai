---
title: "Pagination"
description: "Toutes les routes de liste se parcourent avec un curseur opaque — jamais avec un décalage"
---

Toutes les routes de liste paginées (`GET /automations`, `GET /runs`, `GET /automations/{id}/runs`, `GET /leads`) renvoient la même forme :

```json
{
  "data": [ ],
  "has_more": true,
  "next_cursor": "opaque-cursor-string"
}
```

## Paramètres de requête

| Paramètre | Remarques |
|---|---|
| `limit` | Entier, de 1 à 100, 25 par défaut. Hors de cet intervalle ou non entier → `400 invalid_request`, jamais ramené en silence dans l'intervalle. |
| `cursor` | Chaîne opaque reprise du `next_cursor` d'une réponse précédente. Absent, vide, ou la chaîne littérale `null` : c'est la première page. Un curseur illisible → `400 invalid_request`. |

## Parcourir toutes les pages

Cette boucle utilise [`jq`](https://jqlang.org) pour lire la réponse :

```bash
cursor=""
while :; do
  response=$(curl -s -G "https://core-api.agentova.ai/v1/automations" \
    --data-urlencode "limit=100" \
    --data-urlencode "cursor=$cursor" \
    -H "Authorization: Bearer agk_live_your_key_here")

  printf '%s' "$response" | jq -r '.data[] | "\(.id)  \(.name)"'   # traiter la page

  has_more=$(printf '%s' "$response" | jq -r '.has_more')
  [ "$has_more" = "true" ] || break
  cursor=$(printf '%s' "$response" | jq -r '.next_cursor')
done
```

Un `cursor` vide demande la première page : la même commande fonctionne donc pour toutes les pages.

<Warning>
  Vérifiez toujours `has_more` avant de suivre `next_cursor`. Avec la simulation locale, qui renvoie toujours le même exemple figé, une boucle qui ne vérifie pas `has_more` peut tourner sans fin.
</Warning>

`GET /webhooks` fait exception : un espace de travail a au plus 20 abonnements actifs, la route les renvoie donc tous d'un coup — y compris les abonnements désactivés, jusqu'à leur suppression — sous la forme `{ "data": [ ] }`.

Le curseur est opaque — ne l'analysez pas, ne le conservez pas et ne supposez rien de son format. Sa forme peut changer sans préavis.
